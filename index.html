CloudCampus - AI-ready Multi-Tenant School ERP SaaS.

CloudCampus is an AI-ready multi-tenant School ERP SaaS platform for schools, trusts, and multi-campus organizations. It includes tenant onboarding, role-based access, secure authentication, school isolation, student/staff workflows, academic setup, attendance, homework, exams, fees, notices, reports, audit logging, and deployment-oriented documentation.

Problem

Schools need centralized digital workflows for academics, staff, students, parents, fees, communication, documents, and administration. Manual operations make reporting, access control, and multi-campus expansion difficult.

Solution

CloudCampus models schools as a multi-tenant SaaS platform with role-specific portals, secure onboarding, server-derived tenant/school context, API-first workflows, and controlled staging deployment documentation.

My Role

Founder, backend engineer, and product engineer. I own product scope, backend architecture, API design, tenant isolation decisions, deployment readiness, and roadmap planning.

Business Value

CloudCampus targets school operations digitization: safer role access, cleaner academic/finance workflows, parent/student visibility, and an expansion path for multi-school organizations.

CloudCampus System Design

Scale Target

Long-term architecture target documented for 100,000+ schools and millions of users; current state is local/internal demo and controlled staging validation.

Tenant Isolation

Tenant and school boundaries are explicit. Access context is resolved server-side through authenticated user grants and school-scoped guards.

Auth / RBAC

JWT access tokens, refresh lifecycle, MFA challenge foundation, BCrypt password hashing, and role-aware protected routes across eight roles.

Audit Logging

Sensitive flows such as onboarding, invitations, session events, school mutations, and role changes are designed for audit records without raw secrets.

Database

PostgreSQL-oriented schema with Flyway migrations, tenant/school-scoped tables, report/export foundations, and transactional outbox groundwork.

Deployment

Docker, Docker Compose, Nginx, GitHub Actions, EC2 staging runbooks, rollback guidance, and health/readiness endpoints are present.

Backups

Local PostgreSQL backup/restore drill scripts exist. Hosted backup/restore proof is still a before-pilot roadmap item.

Monitoring Roadmap

Prometheus alert configuration exists as a foundation. Stable hosted monitoring, alerts, logs, and production dashboards remain pending.
